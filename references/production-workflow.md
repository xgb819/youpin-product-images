# 完整套图制作与视觉验收

用于一次制作透明主图、实景图、轮播、详情页和上架文案。单图返修仍读 [correction-playbook.md](correction-playbook.md)。本流程解决“尺寸都对但成品像模板占位、场景重复、产品过小、文字与Logo抢位、只看脚本不看图片”等质量问题。

## 1. 开始排版前先完成素材盘点

解压后按自然序排列全部主图、SKU、详情切片和实拍，先取得尺寸、格式、透明度与文件大小，并生成一张仅供制作核对的素材总览。详情是连续切片时先拼成长图再识别模块；不能把切片边界误当画面边界。

为每个可用画面登记：

- 稳定资产ID、源文件、哈希与长图y坐标；
- 商品/SKU、场景、玩法、功能、细节、配置、参数等角色；
- 主体及关键配件边界；
- 旧广告文字、装饰箭头、尺寸标注和实物印花各自的位置；
- 可安全裁切方向、是否需要去字、是否有可用文字留白。

未看完素材总览和关键原图，不开始批量套模板。聊天截图用于定位问题，制作回到原文件。原素材数量少时减少页数，不生成空场景、重复场景或纯色占位图凑数量。

Windows 下先运行 `powershell -ExecutionPolicy Bypass -File scripts/expand-source-archive.ps1 -Archive /path/to/source.zip -Destination /path/to/extracted-folder`。脚本会把 ZIP 内 `1:1主图` 等非法路径字符安全替换为下划线，避免系统解压悄悄漏图。然后运行 `node scripts/inventory-assets.mjs /path/to/extracted-folder --out /path/to/review`，生成带尺寸、透明度、字节和哈希的 `asset-inventory.json` 以及 `asset-contact-sheet.jpg`。总览只用于定位，仍须打开关键原图和最终成品检查。

## 2. 先做事实表和图位计划

从本款资料提取事实，区分功能、参数、SKU属性、随箱配置和未知项。每张图先写明它承担的唯一信息，再决定版式和源图。推荐保存 `asset-plan.json`，至少包含输出ID、图位、源资产ID、裁切框、修补区域、文案ID和场景ID。

轮播和详情场景默认一图一职：主场景、核心玩法、不同功能、操作、细节、配置分别选不同画面。实景方图与轮播首图按项目要求可共用同一母图；除此之外，同一场景不得只换标题重复使用。原图中存在有效且不重复的场景或小卡片时继续利用，不因预设页数删除。

## 3. 买点必须提供购买价值

核心卖点优先回答“能做什么、怎么玩、解决什么使用问题”，例如互动方式、核心玩法、操控、学习/收纳/充电方式或关键结构。以下内容默认只放SKU、配置或规格，不占核心卖点：

- “粉白两色可选”“多款可选”等颜色/款式数量；
- “标准版/豪华版可选”等版本存在本身；
- “配置齐全”“包装精美”等没有具体使用价值的泛化描述；
- 与其他卖点同义的重复短句。

只有颜色、版本或包装本身带来可说明且有证据的功能差异时，才可转为功能卖点。三条后台核心卖点也遵守此规则，不为接近字数上限填入无意义属性。

## 4. 图素处理按原图优先级执行

先使用原图裁切、等比重取景、去旧字和重新排字；不默认生成背景再贴透明商品。局部AI编辑只允许明确的去字、背景提取、缺口扩展或用户要求的受控改角度，并写出必须保持的产品结构、印花、按钮、接口、配件、颜色与镜头。

编辑后必须与原图并排查看，重点检查商品是否被重画、边缘是否有白边/蓝边、透明图是否残留碎片、扩展区域是否有直线分界、重复纹理、镜像物件或光影跳变。提示词中的“保持不变”不是验收证据。

## 5. 版式应由素材角色决定

- 透明主图：产品完整、尽量贴近中央640安全区，不加背景、文字或投影。
- 实景图：场景铺满且主体完整；不能把横图缩成小卡片后用大面积白色/米色补画布。
- 轮播首图：无附加文字；后续每张承担不同信息，标题在上方安全区，产品不能长期堆在画面底部或被裁切。
- 详情头图：名称与slogan左对齐，正式品牌Logo在右侧200×90示意区。先保留Logo区再测文字，不用临时文字或产品印花代替品牌Logo。
- 详情正文：完整场景可满版排字，操作/配置/参数可用信息模块；两类交替，不把全部页面做成“白底+标题+方框图片”。
- 细节页：配图必须真正展示标题所说的局部，例如“圆润边角”要看到外轮廓弧线，“扬声器开孔”要看到开孔，而不是泛用正面照。

头图实施时将右侧Logo矩形和文字矩形都记录下来：两者不得相交；默认至少留30px视觉间隔，这是本项目保守实施值，不冒称官方标注。空间不足时依次选择真实简称、按词组换成两行或换原图；禁止缩小官方字号、把文字挤入Logo区或移走Logo。

可将画布、`logo_box`、`text_boxes`、`logo_asset`写入 `hero-layout.json`，运行 `node scripts/check-hero-layout.mjs /path/to/hero-layout.json` 检查左右80px安全区、文字/Logo相交和30px实施间隔。几何通过后仍需打开成品确认Logo身份、颜色和视觉比例。

## 6. 导出后必须看实际图片

自动尺寸、字节和安全区检查通过后，还要进行两层目检：

1. 总览：分别生成轮播、详情和SKU总览，检查场景重复、模板重复、节奏、产品大小、明显纯色条与异常留白。
2. 单图100%：打开每张成品，检查文字边缘、Logo、主体四边、手柄/遥控器/小卡片等配件、旧字残留、去字边缘和扩图接缝。

任何图片未实际打开，不得把整套标为完成。脚本成功、文件存在或总览缩略图好看都不能替代单图检查。发现问题按 [correction-playbook.md](correction-playbook.md) 只返工当前图及其共用母图消费者。

## 7. 完整交付门禁

正式交付至少保留：

- 商品事实与文案来源；
- 素材盘点/资产计划；
- 逐模块详情规范核对；
- 图素编辑记录；
- 最终尺寸、格式、字节和安全区报告；
- 逐张视觉验收记录，写明已查看的输出哈希；
- 返修时未改文件的哈希对比。

不满足以下任一项时继续返工，不交付：关键商品/配件被裁切；头图文字侵入Logo区；场景无意义重复；存在旧广告文字或无意义色条；扩图出现接缝；白字重影；主体场景页高度不足项目要求；细节标题与配图不对应；核心卖点被颜色/款式信息占位。
